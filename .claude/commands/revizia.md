Проведи ревизию файла(ов): $ARGUMENTS

Если аргумент не задан — бери файлы, изменённые в рабочем дереве (`git status`).

Сверь с `CLAUDE.md` и с эталоном — любой подглавой из `Файловая система Linux/`.
Проверь по порядку и по каждому пункту скажи «ок» или что именно не так,
с номером строки:

**Разметка**
1. Frontmatter не обёрнут в ```` ```yaml ````; поля `title`, `chapter`, `part`,
   `parts_total`, `status`, `tags` на месте, `tags` — блочным списком.
2. `# H1` дословно совпадает с `title`.
3. Шапка `> [!abstract] <глава> · подглава N из M` + одно-два предложения.
4. Заголовки только `##` и `###`, регистр предложения.
5. Вики-ссылки не обёрнуты в обратные кавычки. Каждая ведёт в реальный файл
   хранилища либо в осмысленное будущее имя вида `NN-Название`.
6. У каждой вставки картинки следующей строкой — `*Рис. N.M. Подпись.*`
   целиком курсивом. Файл лежит в `img/` своей главы, не в корне хранилища.

**Скелет**
7. Есть все четыре концовки и ровно в этом порядке: «Что нужно унести из этой
   подглавы» → «Как это ломается» → «Задачи для самопроверки» → навигация.
8. В «Как это ломается» 3–4 сценария, заголовки — жалобы в «ёлочках»,
   в каждом есть симптом, разбор, команда диагностики и починка.
9. Каждая задача заканчивается строкой `**Как понять, что получилось:**`.
10. Навигация: формат точный, текущий номер жирный без ссылки, и она
    согласована с остальными файлами главы.

**Текст**
11. Тон: на «ты», без канцелярита, без эмодзи, без восклицательных знаков.
12. Типографика: «ёлочки», длинные тире, `…` символом, `→` для стрелок.
13. Сеттинг: `catbox`, `/srv/cats`, знакомые коты. Новых сущностей не больше,
    чем нужно.
14. Вывод команд правдоподобен и внутренне согласован (размеры, inode, даты).
    Флаги существуют на самом деле — сомнительные проверь.
15. Каждое обещание «вернёмся к этому позже» куда-то ведёт.

**Отбор**
16. По каждому содержательному `##` (кроме вводки и четырёх концовок) назови
    одной строкой, чему он служит: вопросу с собеседования (сформулируй его),
    инциденту из «Как это ломается» этой или другой подглавы (назови
    и укажи где) или модели, на которую они
    опираются. Раздел, для которого ответа нет, пометь «кандидат на удаление
    или в читшит».
17. Если есть карточка подглавы — сверь с её «не входит»: соседние механизмы
    упомянуты не больше чем одной фразой со ссылкой.
18. Посчитай слова: `wc -w` по файлу (в UTF-8 локали — в локали C кириллица не считается). Заметно больше 4000 — перепроверь
    пункт 16 строже. Длина сама по себе не дефект; резать объяснения ради
    объёма нельзя.

**Понятность** — не сам, а через субагента
19. Запусти отдельного субагента (инструмент Agent / Task) и дай ему **только
    текст подглавы** — без CLAUDE.md, без карточки, без своих выводов. Роль:
    backend-разработчик, на Linux знает десяток команд, предыдущие главы книги
    читал. Задача: прочитать как учебник и выписать с номерами строк каждое
    место, где он споткнулся:
    - слово, которое не объяснено на месте и не выглядит общеизвестным для
      разработчика;
    - пропущенный шаг: вывод следует, но непонятно откуда;
    - абзац, который пришлось перечитать;
    - утверждение, которое хочется проверить, а команды рядом нет.
    Похвалы и пересказ ему не нужны — только список спотыканий.
20. Разложи спотыкания по трём уровням. Чинится только первый и второй.
    - **Ломает модель** — противоречие с тем, что только что объяснено;
      вывод команды или цифры не сходятся с текстом; шаг, без которого не
      понять следующий раздел или инцидент. Чинить обязательно, это часто
      фактическая ошибка, а не стиль.
    - **Мешает** — термин этой главы использован раньше, чем введён;
      ключевое утверждение без команды, которая его показывает. Чинить, если
      правка — фраза или строка вывода.
    - **Шум** — термин из другой главы (хватит ссылки вперёд), общеизвестное
      разработчику, «хочется проверить» второстепенное. Не чинить.
    Правка ради понятности — фраза, а не абзац. Если для объяснения нужен
    абзац, это материал за границей подглавы: ссылка туда, где он разобран.
    Калибровка: на эталоне 1.1 и 1.5 читатель находит 20–35 спотыканий, из
    них 2–3 первого уровня. Это норма, а не повод переписывать подглаву.

В конце дай список правок в порядке важности. Не правь файл, пока не попросят.
