# Команды и флаги

> [!abstract] Читшит · живой документ
> Формат одинаковый у всех: назначение → флаги → примеры. Шаблон для новых команд — в самом конце.

---

## Общие правила

- Короткие флаги склеиваются: `ls -l -a -h` = `ls -lah`
- Длинные не склеиваются: `--all --human-readable`
- Флаг с аргументом: `-n 5` или `-n5`, длинный — `--lines=5`
- `--` завершает список опций. Нужно для файлов, начинающихся с дефиса: `rm -- -file.txt`
- `команда --help` — быстрая справка, `man команда` — полная
- Встроенные команды shell (`cd`, `alias`, `echo`) справки через `--help` не имеют, для них `help cd`

## Навигация и базовое

### pwd — где я сейчас

|Флаг|Что делает|
|---|---|
|`-L`|логический путь (по умолчанию) — как ты сюда пришёл, с симлинками|
|`-P`|физический путь — реальный, симлинки развёрнуты|

```bash
cd /bin && pwd        # /bin
cd /bin && pwd -P     # /usr/bin  (потому что /bin -> /usr/bin)
```

### cd — сменить каталог

Встроенная команда shell, не программа. Аргументы важнее флагов.

|Аргумент|Что делает|
|---|---|
|`cd`|в домашний каталог|
|`cd -`|в предыдущий каталог (туда-обратно)|
|`cd ~user`|в домашний каталог другого юзера|
|`cd ..`|на уровень вверх|
|`-P`|разворачивать симлинки при переходе|

```bash
cd /var/log
cd /etc/nginx
cd -          # обратно в /var/log
```

### ls — список файлов

|Флаг|Что делает|
|---|---|
|`-l`|длинный формат: права, владелец, размер, дата|
|`-a`|показать скрытые (включая `.` и `..`)|
|`-A`|скрытые, но без `.` и `..`|
|`-h`|размеры человекочитаемо (только вместе с `-l`)|
|`-t`|сортировать по времени изменения, свежие сверху|
|`-S`|сортировать по размеру|
|`-r`|развернуть сортировку|
|`-i`|показать номер inode|
|`-d`|сам каталог, а не его содержимое|
|`-R`|рекурсивно вглубь|
|`-1`|по одному в строку (удобно для пайпов)|
|`-F`|добавить суффикс типа: `/` каталог, `*` исполняемый, `@` симлинк|
|`--time-style=long-iso`|нормальные даты `2026-09-03 14:22`|

```bash
ls -lah                # самый частый набор
ls -ltrh               # свежие файлы внизу — удобно для логов
ls -li                 # проверить, хардлинки ли это (одинаковый inode)
ls -ld /var/log        # права на сам каталог
```

### touch — создать пустой файл / обновить время

|Флаг|Что делает|
|---|---|
|`-c`|не создавать, если файла нет|
|`-a`|менять только время доступа (atime)|
|`-m`|менять только время изменения (mtime)|
|`-d "строка"`|задать конкретное время: `-d "2026-01-01 10:00"`|
|`-r файл`|взять время с другого файла|

```bash
touch config.yml                    # создать пустой
touch -r old.txt new.txt            # скопировать метку времени
```

### mkdir — создать каталог

|Флаг|Что делает|
|---|---|
|`-p`|создать всю цепочку родителей, не ругаться если уже есть|
|`-m`|сразу задать права: `-m 700`|
|`-v`|сказать, что создал|

```bash
mkdir -p ~/projects/app/src/utils     # создаст все уровни разом
mkdir -m 700 ~/.secrets
```

### rmdir — удалить пустой каталог

|Флаг|Что делает|
|---|---|
|`-p`|удалить и родителей, если стали пустыми|
|`--ignore-fail-on-non-empty`|молча пропускать непустые|

Работает **только с пустыми**. Для непустых — `rm -r`. На практике `rmdir` почти не нужен, зато он безопасен: не удалит ничего ценного по ошибке.

### rm — удалить

|Флаг|Что делает|
|---|---|
|`-r`|рекурсивно, для каталогов|
|`-f`|не спрашивать, не ругаться на отсутствующие|
|`-i`|спрашивать про каждый файл|
|`-I`|спросить один раз, если файлов больше трёх|
|`-d`|удалить пустой каталог|
|`-v`|показывать что удаляет|
|`--one-file-system`|не уходить на другие смонтированные ФС|

```bash
rm -rf build/
rm -- -weird-file.txt          # файл, имя которого начинается с дефиса
```

> [!warning] Три способа выстрелить себе в ногу
> - `rm -rf mydir/` **со слэшем** на симлинке пройдёт по ссылке и вычистит цель. Без слэша удалит саму ссылку
> - `rm -rf "$DIR/"` при пустой переменной `$DIR` превращается в `rm -rf /`. Всегда проверяй переменную перед подстановкой
> - пробел не там: `rm -rf /home /user` вместо `/home/user`

### cp — копировать

|Флаг|Что делает|
|---|---|
|`-r` / `-R`|рекурсивно, для каталогов|
|`-a`|архивный режим: `-dR --preserve=all`. Сохраняет права, владельца, время и симлинки|
|`-p`|сохранить права и время|
|`-i`|спросить перед перезаписью|
|`-n`|не перезаписывать существующие|
|`-u`|копировать, только если источник новее|
|`-v`|показывать что копирует|
|`-l`|создать хардлинки вместо копирования|
|`-s`|создать симлинки вместо копирования|
|`-L`|разыменовать симлинки (скопировать содержимое цели)|

```bash
cp -a /etc/nginx /backup/nginx        # честная копия с правами
cp -r src/ dst/
```

> [!tip] Про слэш
> `cp -r src dst` — если `dst` существует, положит `src` **внутрь**. Если нет — создаст `dst` как копию `src`. Частый источник сюрпризов.

### mv — переместить или переименовать

Одна команда для обоих: переименование — это перемещение внутри каталога.

|Флаг|Что делает|
|---|---|
|`-i`|спросить перед перезаписью|
|`-n`|не перезаписывать|
|`-u`|только если источник новее|
|`-v`|показывать что делает|
|`-b`|сделать резервную копию перезаписываемого|
|`-t каталог`|указать назначение первым (для `xargs`)|

```bash
mv old.txt new.txt                 # переименовать
mv *.log /var/log/archive/         # переместить пачкой
```

Внутри одной ФС `mv` мгновенный — меняется только запись в каталоге, данные не двигаются. Между разделами это реальное копирование + удаление, и оно долгое.

## Просмотр содержимого

### less — постраничный просмотр

|Флаг|Что делает|
|---|---|
|`-N`|номера строк|
|`-S`|не переносить длинные строки (скроллить вбок)|
|`-i`|поиск без учёта регистра|
|`-R`|показывать цвета (ANSI-коды)|
|`-F`|выйти сразу, если содержимое влезло на экран|
|`-X`|не очищать экран при выходе|
|`+F`|режим слежения, как `tail -f`|
|`+G`|открыть сразу в конце|

Клавиши внутри:

|Клавиша|Действие|
|---|---|
|`/текст`|поиск вперёд, `?текст` — назад|
|`n` / `N`|следующее / предыдущее совпадение|
|`g` / `G`|в начало / в конец|
|`Space` / `b`|страница вперёд / назад|
|`&текст`|показать только строки с совпадением (как grep)|
|`F`|включить слежение за файлом, `Ctrl+C` — выйти из него|
|`q`|выход|

```bash
less +G /var/log/syslog        # открыть в конце
journalctl -u nginx | less -R  # с цветами
```

`man` использует `less` внутри — все эти клавиши работают и там.

### head — начало файла

|Флаг|Что делает|
|---|---|
|`-n N`|первые N строк (по умолчанию 10)|
|`-n -N`|всё, **кроме** последних N строк|
|`-c N`|первые N байт|
|`-q`|не печатать заголовки при нескольких файлах|

```bash
head -n 20 access.log
head -c 512 /dev/urandom | xxd
```

### tail — конец файла

|Флаг|Что делает|
|---|---|
|`-n N`|последние N строк|
|`-n +N`|начиная со строки N до конца|
|`-f`|следить за дописыванием|
|`-F`|то же, но переоткрывать файл, если его пересоздали|
|`-c N`|последние N байт|
|`--pid=PID`|закончить слежение, когда процесс умрёт|

```bash
tail -f /var/log/nginx/error.log
tail -n 100 -f app.log             # показать хвост и следить дальше
tail -n +2 data.csv                # пропустить заголовок
```

**`-F` вместо `-f`** — правило для логов, которые ротируются. `-f` держит дескриптор, и после ротации ты смотришь в мёртвый файл. `-F` заметит подмену и переоткроет.

## Информация о системе

### whoami / id — кто я

`whoami` флагов не имеет. Полезнее `id`:

|Команда|Что показывает|
|---|---|
|`whoami`|текущее имя пользователя|
|`id`|UID, GID и все группы|
|`id -u`|только UID (0 = root)|
|`id -un`|имя (то же, что whoami)|
|`id -nG`|имена всех групп|
|`id username`|то же про другого юзера|
|`echo $SUDO_USER`|кто вызвал sudo (внутри sudo-сессии)|
|`who` / `w`|кто вообще залогинен в систему|

```bash
[ "$(id -u)" -eq 0 ] || { echo "нужен root"; exit 1; }    # проверка в скриптах
```

### which — где лежит команда

|Флаг|Что делает|
|---|---|
|`-a`|показать **все** совпадения в `$PATH`, а не первое|

Ограничение: `which` — внешняя программа, она не видит алиасы, функции и встроенные команды shell. В bash лучше:

|Команда|Чем лучше|
|---|---|
|`type -a ls`|покажет алиас, функцию, builtin и файл — всё сразу|
|`command -v cmd`|самый переносимый вариант для скриптов|

```bash
which -a python3      # вдруг их два в разных путях
type -a ll            # ll is aliased to `ls -alF'
```

### top — процессы в реальном времени

|Флаг|Что делает|
|---|---|
|`-d N`|интервал обновления в секундах|
|`-u user`|только процессы юзера|
|`-p PID`|только конкретные процессы|
|`-o поле`|сортировать по полю: `-o %MEM`|
|`-b`|batch-режим, без интерактива (для скриптов и пайпов)|
|`-n N`|сделать N обновлений и выйти|
|`-H`|показывать потоки, а не процессы|

Клавиши внутри:

|Клавиша|Действие|
|---|---|
|`P` / `M` / `T`|сортировать по CPU / памяти / времени|
|`k`|убить процесс (спросит PID и сигнал)|
|`r`|изменить приоритет (renice)|
|`c`|показать полную командную строку|
|`1`|разбить CPU по ядрам|
|`u`|фильтр по юзеру|
|`z`|цвета|
|`W`|сохранить настройки в `~/.toprc`|
|`q`|выход|

```bash
top -b -n 1 | head -20            # снапшот в текстовый файл
top -o %MEM                       # кто ест память
```

`htop` (`apt install htop`) — то же самое, но с мышкой, поиском и деревом процессов. Для живой работы удобнее.

### lsof — какие файлы открыты

Помни, что «файл» тут в широком смысле: сокеты, пайпы, устройства.

|Флаг|Что делает|
|---|---|
|`-i`|сетевые соединения|
|`-i :80`|кто держит порт 80|
|`-i tcp`|только TCP|
|`-p PID`|что открыл конкретный процесс|
|`-u user`|что открыл юзер|
|`-c nginx`|по имени команды|
|`+D /path`|всё открытое внутри каталога (рекурсивно)|
|`+L1`|файлы с нулём ссылок — **удалённые, но открытые**|
|`-t`|вывести только PID (для пайпа в `kill`)|
|`-n -P`|не резолвить имена хостов и портов (сильно быстрее)|

```bash
sudo lsof -i :8080                 # кто занял порт
sudo lsof +L1                      # почему df и du расходятся
sudo lsof -p 1234                  # что держит процесс
sudo lsof +D /mnt/data             # почему не размонтируется
```

Почти всегда нужен `sudo` — иначе увидишь только свои процессы.

### df — сколько места на разделах

|Флаг|Что делает|
|---|---|
|`-h`|человекочитаемо (степени 1024)|
|`-H`|то же, но степени 1000|
|`-i`|считать inode вместо байт|
|`-T`|показать тип файловой системы|
|`-a`|включая псевдо-ФС|
|`-x tmpfs`|исключить тип|
|`-t ext4`|только указанный тип|
|`--output=source,size,used,pcent,target`|выбрать колонки|

```bash
df -h                    # база
df -hT -x tmpfs          # только настоящие диски
df -i                    # «No space left» при свободных гигабайтах
df -h /var/lib/docker    # какой раздел обслуживает этот путь
```

### du — сколько занимает каталог

|Флаг|Что делает|
|---|---|
|`-h`|человекочитаемо|
|`-s`|только итог, без разбивки|
|`-a`|считать и файлы, не только каталоги|
|`-c`|добавить строку total|
|`-x`|не уходить на другие файловые системы|
|`-d N` / `--max-depth=N`|глубина вложенности|
|`--apparent-size`|логический размер вместо занятых блоков (для sparse-файлов)|
|`--exclude='*.log'`|пропустить по маске|

```bash
du -xh --max-depth=1 / 2>/dev/null | sort -h    # с этого начинается разбор «диск кончился»
du -sh *  | sort -h                             # что жирного в текущем каталоге
du -sh .[!.]*                                   # то же для скрытых
```

## Права и пользователи

### sudo — выполнить от имени root

|Флаг|Что делает|
|---|---|
|`-i`|полноценный login-shell рута, с его окружением и `~`|
|`-s`|shell рута, но с твоим окружением|
|`-u user`|выполнить от имени другого юзера, не root|
|`-l`|показать, что тебе вообще разрешено|
|`-k`|сбросить кэш пароля (обычно он живёт 15 минут)|
|`-E`|пробросить свои переменные окружения|
|`-e файл`|безопасно отредактировать файл (= `sudoedit`)|

```bash
sudo !!                            # повторить прошлую команду с sudo
sudo -u postgres psql              # зайти в psql от имени postgres
sudo -l                            # что мне разрешено на этом сервере
```

> [!warning] Классическая ловушка
> `sudo echo x > /root/f` **не сработает** — редирект выполняет твой shell, у которого прав нет. Правильно:
>
> ```bash
> echo x | sudo tee /root/f > /dev/null
> ```

### su — переключиться на другого пользователя

|Флаг|Что делает|
|---|---|
|`-` или `-l`|login-shell: полное окружение целевого юзера, переход в его `~`|
|`-c 'команда'`|выполнить одну команду и выйти|
|`-s /bin/bash`|задать shell (если у юзера прописан nologin)|

```bash
su -                        # стать root (нужен пароль root)
su - postgres               # стать другим юзером
su - postgres -c 'psql -l'
```

**`su -` почти всегда лучше, чем `su`.** Без дефиса ты получаешь права нового юзера, но со **старым окружением**: чужой `$PATH`, чужой `$HOME`. Отсюда «команда не найдена» под рутом.

В Ubuntu аккаунт root по умолчанию заблокирован, пароля у него нет — поэтому там `sudo -i` вместо `su -`.

## Пакетные менеджеры

### apt — Debian / Ubuntu

|Команда|Что делает|
|---|---|
|`apt update`|обновить список пакетов (не трогает сами пакеты)|
|`apt upgrade`|обновить установленные|
|`apt full-upgrade`|то же, но разрешено удалять конфликтующие|
|`apt install pkg`|установить|
|`apt remove pkg`|удалить, конфиги оставить|
|`apt purge pkg`|удалить вместе с конфигами|
|`apt autoremove`|снести осиротевшие зависимости|
|`apt search текст`|найти пакет|
|`apt show pkg`|подробности|
|`apt list --installed`|что стоит|
|`apt list --upgradable`|что можно обновить|

|Флаг|Что делает|
|---|---|
|`-y`|отвечать «да» на всё (обязательно в скриптах)|
|`-s`|симуляция, ничего не менять|
|`--no-install-recommends`|без рекомендованных пакетов, экономит место|
|`--only-upgrade`|обновить, но не ставить если не установлен|

```bash
sudo apt update && sudo apt upgrade -y
sudo apt install --no-install-recommends nginx
sudo apt autoremove --purge      # чистка /boot от старых ядер
```

### apt-get — то же, но для скриптов

`apt` — новая обёртка для людей: прогресс-бар, цвета, более удобный вывод. Но её **вывод не стабилен между версиями**, поэтому в скриптах и Dockerfile используют `apt-get` — у него гарантия обратной совместимости.

Отличия в командах:

|apt-get|Комментарий|
|---|---|
|`apt-get dist-upgrade`|= `apt full-upgrade`|
|`apt-get clean`|очистить кэш скачанных .deb|
|`apt-get autoclean`|удалить только устаревшие .deb из кэша|

Поиск и информация живут в отдельной утилите:

```bash
apt-cache search nginx
apt-cache policy nginx        # какая версия установлена и откуда придёт обновление
```

Уровнем ниже — `dpkg`, он работает с отдельными .deb и не умеет в зависимости:

```bash
dpkg -l | grep nginx          # список установленного
dpkg -L nginx                 # какие файлы принёс пакет
dpkg -S /usr/sbin/nginx       # какому пакету принадлежит файл
sudo dpkg -i package.deb      # поставить локальный .deb
```

### dnf — Fedora / RHEL / Rocky / Alma

|Команда|Что делает|
|---|---|
|`dnf install pkg`|установить|
|`dnf remove pkg`|удалить|
|`dnf upgrade`|обновить всё (`update` — синоним)|
|`dnf search текст`|найти|
|`dnf info pkg`|подробности|
|`dnf list installed`|что стоит|
|`dnf provides */nginx.conf`|какой пакет даёт этот файл|
|`dnf history`|журнал операций|
|`dnf history undo N`|**откатить транзакцию**|
|`dnf group install "Development Tools"`|группа пакетов|
|`dnf clean all`|очистить кэш|

|Флаг|Что делает|
|---|---|
|`-y`|без вопросов|
|`--refresh`|обновить метаданные перед операцией|
|`--nobest`|разрешить не самую свежую версию, если лучшая конфликтует|
|`--skip-broken`|пропустить проблемные пакеты|

Главное отличие от apt: **отдельного `update` для метаданных нет** — dnf обновляет их сам по таймауту. И есть откат установок через `history undo`, чего в apt нет.

Уровнем ниже — `rpm` (аналог dpkg): `rpm -qa`, `rpm -ql pkg`, `rpm -qf /path/to/file`.

## Shell: вывод, цепочки, алиасы

### echo — напечатать текст

|Флаг|Что делает|
|---|---|
|`-n`|без перевода строки в конце|
|`-e`|интерпретировать escape-последовательности: `\n`, `\t`, `\033`|
|`-E`|не интерпретировать (по умолчанию)|

```bash
echo "$PATH"
echo -n "без переноса"
echo -e "строка1\nстрока2"
```

Тонкость: `echo` есть и как встроенная команда bash, и как `/bin/echo`, и они по-разному относятся к `-e`. Для чего-то серьёзного лучше `printf` — он предсказуем везде:

```bash
printf '%s\n' "$var"
printf '%-10s %5d\n' "name" 42     # форматирование колонок
```

### Несколько команд в одной строке

|Разделитель|Смысл|
|---|---|
|`;`|выполнить по очереди, независимо от результата|
|`&&`|выполнить вторую, **только если первая успешна** (код возврата 0)|
|`\|\|`|выполнить вторую, только если первая **упала**|
|`&`|запустить в фоне и не ждать|
|`\|`|пайп: stdout первой → stdin второй|

```bash
cd /tmp; ls                              # ls выполнится в любом случае
cd /tmp && ls                            # ls только если cd удался — так безопаснее
make || echo "сборка упала"
sudo apt update && sudo apt upgrade -y   # каноничная связка
command1 & command2 &                    # обе в фон
```

Группировка:

|Синтаксис|Что делает|
|---|---|
|`( cmd1; cmd2 )`|выполнить в **субшелле** — изменения `cd` и переменных не выйдут наружу|
|`{ cmd1; cmd2; }`|выполнить в текущем shell (нужны пробелы и `;` перед `}`)|

```bash
( cd /tmp && ls )       # после выполнения ты остался там же, где был
cmd1 && { cmd2; cmd3; } # обе выполнятся, только если cmd1 успешна
```

Проверить результат последней команды: `echo $?` (0 = успех).

### alias — сокращение для команды

|Форма|Что делает|
|---|---|
|`alias`|показать все алиасы|
|`alias ll='ls -lah'`|создать|
|`alias ll`|показать один|
|`unalias ll`|удалить|
|`unalias -a`|удалить все|
|`\ls`|выполнить настоящую команду в обход алиаса|
|`type ll`|проверить, алиас это или что-то другое|

```bash
alias ll='ls -lahF'
alias ..='cd ..'
alias dfh='df -hT -x tmpfs'
alias ports='sudo lsof -i -P -n | grep LISTEN'
```

Алиас живёт только в текущей сессии. Чтобы остался — в `~/.bashrc` (или `~/.zshrc`), затем `source ~/.bashrc`.

Два ограничения: алиасы **не принимают аргументы** в середине и **не работают в скриптах** (там неинтерактивный shell). Если нужны аргументы — пиши функцию:

```bash
mkcd() { mkdir -p "$1" && cd "$1"; }
```

### man — документация

|Флаг|Что делает|
|---|---|
|`-k текст`|поиск по описаниям всех страниц (= `apropos`)|
|`-f команда`|краткое описание (= `whatis`)|
|`-a`|показать все страницы с этим именем подряд|
|`N`|номер раздела: `man 5 passwd`|

Разделы (одно имя может быть в нескольких):

|№|Что там|
|---|---|
|1|пользовательские команды|
|2|системные вызовы|
|3|библиотечные функции|
|5|**форматы файлов и конфиги**|
|8|команды администрирования|

```bash
man 1 passwd      # команда смены пароля
man 5 passwd      # формат файла /etc/passwd
man -k socket     # найти всё про сокеты
```

Внутри работает `less`, поэтому доступны `/поиск`, `n`, `g`, `G`, `q`.

Часто короче и полезнее: `команда --help`. А ещё есть `tldr` (`apt install tldr`) — примеры вместо полотна текста.

## Потоки и обработка текста

Механика — в главе «Потоковая обработка текста»: [[01-Потоки и перенаправления]], [[02-Конвейеры]], [[03-sed]], [[04-awk и jq]].

### Перенаправления — куда ведут дескрипторы 0, 1, 2

|Запись|Что делает|
|---|---|
|`> f`|stdout в файл; файл создаётся или **обрезается до старта команды**|
|`>> f`|stdout в конец файла|
|`< f`|файл в stdin|
|`2> f`|stderr в файл|
|`> f 2>&1`|stdout и stderr в файл (порядок важен)|
|`&> f`, `&>> f`|то же коротко, только bash|
|`> f 2>/dev/null`|вывод в файл, ошибки выбросить|
|`< /dev/null`|пустой stdin|
|`<<EOF … EOF`|here-doc: текст до строки `EOF` в stdin; `<<'EOF'` — без подстановок|
|`<<< "строка"`|here-string: одна строка в stdin|
|`set -o noclobber`|`>` отказывается затирать существующий файл|
|`>\| f`|перезаписать несмотря на `noclobber`|

```bash
cmd > out.log 2>&1                 # всё в лог
find /srv -name '*.jpg' > list.txt 2>/dev/null
ls -l /proc/self/fd                # куда ведут дескрипторы
ls -l /proc/PID/fd/{0,1,2}         # то же у чужого процесса
while read y; do ssh -n nas "du -sh /backup/$y"; done < years.txt
```

**`2>&1` копирует то, куда 1 ведёт сейчас**, и перенаправления идут слева направо: `cmd 2>&1 > f` оставляет ошибки на экране. `sort f > f` даёт пустой файл. В `/bin/sh` (dash, cron) `&>` значит «в фон и обрезать файл» — там только `> f 2>&1`.

### Конвейер — `|`, коды возврата, буферизация

|Запись|Что делает|
|---|---|
|`a \| b`|stdout `a` в stdin `b`; обе стартуют одновременно, между ними буфер 64 КБ|
|`a 2>&1 \| b`|в трубу и stdout, и stderr|
|`"${PIPESTATUS[@]}"`|коды всех звеньев последнего конвейера (только bash)|
|`set -o pipefail`|код конвейера — неудача любого звена; `set +o pipefail` — выключить|
|`grep --line-buffered`|построчный вывод в трубу|
|`stdbuf -oL cmd`|то же для программ на stdio; Python — `python3 -u`|

```bash
tar cf - /srv/cats | gzip > cats.tar.gz; echo "${PIPESTATUS[@]}"   # 2 0 — tar упал
tail -F access.log | grep --line-buffered '" 500 ' | grep -v healthcheck
cat /proc/PID/wchan; echo          # pipe_write — писатель ждёт читателя
```

**Код 141 = 128 + SIGPIPE**: `head`, `grep -q` закрыли трубу раньше конца данных. Под `pipefail` это выглядит как ошибка. В трубу и файл программы пишут блоками по 4 КБ — мониторинг через `grep | grep` молчит без `--line-buffered`.

### tee — разветвить поток

|Флаг|Что делает|
|---|---|
|без флагов|stdin → stdout и в файл (файл обрезается)|
|`-a`|дописывать в файл|

```bash
./backup.sh 2>&1 | tee -a backup.log
grep '" 500 ' access.log | tee /tmp/step1.txt | wc -l    # посмотреть промежуточный шаг
echo 10 | sudo tee /proc/sys/vm/swappiness                # файл открывает tee под root
```

Без `2>&1` перед `|` ошибки пройдут мимо `tee` прямо на экран.

### sort — упорядочить строки

|Флаг|Что делает|
|---|---|
|`-n`|как числа|
|`-h`|как размеры с суффиксами: `900K` < `2.1G`|
|`-r`|в обратном порядке|
|`-u`|без повторов|
|`-t X`|разделитель полей|
|`-k N,N`|сортировать по полю N (только по нему)|

```bash
du -sh /srv/cats/* | sort -rh | head
sort -t: -k3,3 -n /etc/passwd
LC_ALL=C sort list.txt             # порядок по байтам, одинаковый везде
```

**`-n` не понимает суффиксы**: читает число до буквы, и `312M` окажется больше `6.2G`. Вывод `du -h` — только `sort -h`. Порядок текстовой сортировки зависит от локали.

### uniq — схлопнуть повторы

|Флаг|Что делает|
|---|---|
|`-c`|писать число повторов|
|`-d`|только повторяющиеся строки|

```bash
cut -d' ' -f1 access.log | sort | uniq -c | sort -rn | head    # топ IP
md5sum /srv/cats/*/*.jpg | cut -d' ' -f1 | sort | uniq -d     # дубликаты фото
```

Схлопывает только **соседние** строки — перед `uniq` почти всегда `sort`.

### cut — вырезать поле

|Флаг|Что делает|
|---|---|
|`-d X`|разделитель — один символ|
|`-f N`, `-f 1,7`, `-f 2-4`|номера полей|

```bash
cut -d: -f1,7 /etc/passwd
cut -d' ' -f1 access.log
```

**Два пробела подряд — пустое поле между ними.** На выводе, выровненном пробелами (`ps`, `df`, `ls -l`), `cut` даёт пустоту — там нужен `awk`.

### tr — заменить и выбросить символы

|Форма|Что делает|
|---|---|
|`tr 'A-Z' 'a-z'`|заменить символы первого набора на символы второго|
|`-d 'набор'`|удалить символы|
|`-s 'набор'`|схлопнуть повторы подряд в один|

```bash
ls | tr 'A-Z' 'a-z'
tr -d '\r' < from-windows.txt > fixed.txt
printf 'a\n\n\nb\n' | tr -s '\n'
```

Имя файла аргументом не принимает (`tr: extra operand`) — только stdin, через `<` или `|`.

### sed — потоковый редактор

|Форма|Что делает|
|---|---|
|`-n`|не печатать строки по умолчанию|
|`'Np'`, `'N,Mp'`, `'$p'`|напечатать строку N, диапазон, последнюю|
|`'N,Mp;Mq'`|то же и выйти, не дочитывая файл|
|`'/re/p'`, `'/re/d'`|напечатать / выбросить строки по регулярке|
|`'/начало/,/конец/p'`|блок между маркерами|
|`'s/a/b/'`, `'s/a/b/g'`|заменить первое / все совпадения в строке|
|`&`, `\1`|в замене: всё совпадение / первая группа|
|`s\|a\|b\|`, `s#a#b#`|другой разделитель|
|`-E`|ERE вместо BRE|
|`-e … -e …`|несколько выражений|
|`-i`, `-i.bak`|«на месте»: новый файл переименовывается поверх; с копией|
|`--follow-symlinks`|с `-i`: править цель ссылки, а не заменять ссылку|

```bash
sed -n '100,200p' access.log
sed -e '/^\s*#/d' -e '/^\s*$/d' /etc/ssh/sshd_config    # конфиг без комментариев
sed -E 's#/srv/cats(/|$)#/data/cats\1#' gallery.yml | diff gallery.yml -   # сначала посмотреть
sed -i.bak 's/8080/8081/' gallery.yml
readlink -f /etc/nginx/sites-enabled/catgallery       # куда ведёт ссылка, чтобы править цель
```

**`sed -i` подменяет файл**: новый inode, нужен `w` на каталоге, жёсткие ссылки отвязываются, симлинк становится обычным файлом. Сначала без `-i` и через `diff`. На маке BSD `sed`: там `-i ''`, а GNU примет `''` за скрипт; `-i.bak` понимают оба. Узнать, какой `sed`: `sed --version`.

### awk — поля и агрегация

|Форма|Что делает|
|---|---|
|`'{print $1}'`|первое поле; разделитель — любое число пробелов и табов|
|`-F:`, `-F'"'`|свой разделитель|
|`$0`, `NF`, `$NF`, `NR`|вся строка, число полей, последнее поле, номер строки|
|`'$7 >= 500'`|шаблон без действия — печатать подходящие строки|
|`'/re/ {…}'`|действие для строк с регуляркой|
|`BEGIN {…}`, `END {…}`|до первой строки / после последней|
|`c[$1]++` + `for (k in c)`|подсчёт по ключу|
|`printf "%s %d\n", a, b`|форматированный вывод|

```bash
awk '{c[$1]++} END {for (ip in c) print c[ip], ip}' access.log | sort -rn | head
awk '{s += $8} END {printf "%.0f\n", s/NR}' access.log     # средний размер
ps aux | awk '$4 > 5'                                     # процессы > 5% памяти
ps -eo pid,comm | awk '$2 == "gallery" {print $1}'        # PID по точному имени
awk '{print NF}' access.log | sort -n | uniq -c           # сколько полей в строках
```

**Пробел внутри кавычек — тоже разделитель**: поля правее user-agent меняют номер от строки к строке. Последнее поле — `$NF`, разбор по кавычкам — `-F'"'`. Порядок `for (k in a)` не определён — дальше `sort`. Больше 3–4 строк программы — повод взять Python.

### jq — JSON как данные

|Форма|Что делает|
|---|---|
|`'.'`|весь объект, с отступами|
|`'.поле'`|значение по имени|
|`'.[]'`, `'.[].поле'`|разложить массив / поле каждого элемента|
|`'select(.status >= 500)'`|пропустить только подходящие объекты|
|`-r`|строки без кавычек|
|`-c`|объект одной строкой|

```bash
jq -c 'select(.status >= 500)' access.json | wc -l
jq -r '.ip' access.json | sort | uniq -c | sort -rn | head
jq -r '.rt' access.json | awk '{s += $1} END {print s/NR}'
curl -s http://localhost:8081/api/albums | jq -r '.[].title'
```

`grep` по JSON ломается на пробелах (`"status": 500` против `"status":500`), порядке полей и типах. Ставится отдельно: `apt install jq`, `dnf install jq`.
